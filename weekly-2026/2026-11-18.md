### LLVM/Clang/LLDB/LLD

本节内容来自 [LLVM Weekly 第 672 期](http://llvmweekly.org/issue/672)，
[Alex Bradbury](https://www.linkedin.com/in/alex-bradbury/) 大哥持续稳定输出。

- Iason Karaprodromidis 在 LLVM 项目博客上撰文，介绍其 GSoC 项目：[为 LLDB 增加 Fortran 支持](https://blog.llvm.org/posts/2026-09-07-gsoc-add-fortran-support-to-lldb/)。

- EuroLLVM 2027 敬请留出档期：[将于 4 月 26 日至 28 日在波尔图（Porto）举行](https://discourse.llvm.org/t/save-the-date-2027-eurollvm-april-26-28/92771)。程序委员会（program committee）志愿者征集现已开放。

- Meta 工程博客发文，介绍[扩展 LLDB 以调试横跨 CPU 与 GPU 的应用程序](https://engineering.fb.com/2026/11/09/developer-tools/extending-lldb-to-debug-applications-that-span-cpus-and-gpus/)。

- LLVM libc 的网站经过重新设计，[现在为每个头文件给出完整度指标](https://libc.llvm.org/headers/index.html)。

- GNU Tools Cauldron 2026 的[录像现已上线](https://www.youtube.com/playlist?list=PLCosWOOi4IhM)。

- 【是个大问题了】 Eugen Zalenko 提议[限制由 AI/机器人辅助、且提交者没有 triage 权限的 issue 创建速率](https://discourse.llvm.org/t/limit-rate-of-ai-bot-assisted-issues-creation-without-triage-role/92792)。
- Aaron Ballman 有意[发起一个社区浮点工作组](https://discourse.llvm.org/t/starting-a-community-floating-point-working-group/92783)。
- 关于 ELF 上 compact unwind 的圆桌讨论记录[现已发布](https://discourse.llvm.org/t/compact-unwind-on-elf-round-table-notes/92769)。
- Louis Dionne [介绍了 LNT v5 的工作进展](https://discourse.llvm.org/t/rfc-proposing-a-major-lnt-update-lnt-v5/91595/18)。
- Harrison Hao 发布 RFC，讨论[废弃并移除对 R600/TeraScale 的支持](https://discourse.llvm.org/t/rfc-amdgpu-deprecating-and-removing-llvm-s-r600-terascale-backend/92840)，此前已确认 Mesa 不再依赖它。
- Slava Zakharin 发布 RFC（并附设计文档），讨论[在 LLVM IR 中表达 Fortran 别名规则：可选方案与代价](https://discourse.llvm.org/t/rfc-representing-fortran-aliasing-rules-in-llvm-ir-options-and-costs/92828)。
- Alina Sbirlea 希望[把 LLVM 形式化验证工具托管为 LLVM 项目的一部分](https://discourse.llvm.org/t/rfc-host-llvm-formal-verification-tools-as-part-of-llvm-project/92824)，即建立一个共享输入测试用例及其对应期望工具输出的中心仓库。讨论中涉及：这批测试用例究竟有多大用处、是否应改为向 monorepo 引入更多工具、抑或提供一个 Compiler Explorer 实例。
- Andrzej Warzyński 与 Federico Bruzzone 希望[让 MLIR 的 CODEOWNERS 与实际在积极评审的人对齐](https://discourse.llvm.org/t/rfc-mlir-align-codeowners-with-active-reviewing/92830)。
- Kay Hicketts 与 Valentyn Yukhymenko 分享了一份关于[静态分析的用户自定义标注](https://discourse.llvm.org/t/rfc-user-defined-annotations-for-static-analysis/92694)的 RFC。该机制让库的维护者能够描述其 API 应如何被 `clang-tidy` 之类的工具解读。
- Md Abdullah Shahneous Bari 发起讨论：[改变 MLIR linalg 与 vector 操作上 fast-math 标志的处理方式](https://discourse.llvm.org/t/rfc-mlir-linalg-vector-fast-math-flags-on-linalg-and-vector-ops/92764/1)。

### RT-Thread 社区

- BLK_PARTITION ioctl 把用户态裸指针直接当内核写地址, 非特权进程可任意改写内核内存, 修复新增 294 行：[drivers][block] prevent arbitrary kernel write via BLK_PARTITION ioctl on RT-Smart](https://github.com/RT-Thread/rt-thread/pull/11981)
- serial_v2 的 DMA ping 缓冲恒偏出 32 字节 cache 行 12 字节, STM32H7 上失效越界踩坏相邻堆块：[Bug] serial_v2: DMA rx ping buffer is not cache-line aligned — D-cache invalidate overruns into the adjacent heap chunk (STM32H7: tx_fifo ringbuffer header reverts, next write asserts)](https://github.com/RT-Thread/rt-thread/issues/12063)
- RISC-V 切换上下文漏存 fs0 至 fs11 与 fcsr, 两个浮点线程互读对方结果, 五个文件补 117 行：[libcpu][riscv] fix: preserve FPU state across context switches](https://github.com/RT-Thread/rt-thread/pull/12006)
- 芯擎 D213 板级包三天走完评审合入, 平头哥 C906 配 128 MiB DDR3, 三十个文件新增 1783 行：[bsp][artinchip] Add initial D213ECV-DEMO-V4-0 support](https://github.com/RT-Thread/rt-thread/pull/12058)
- iso9660 目录名长度为 0 或 1 时减法下溢成无界内核写, 报告后十七分钟出修复：[dfs][iso9660] fix: validate directory record name length](https://github.com/RT-Thread/rt-thread/pull/12062)

- FlagTree 把昇腾后端整体迁到 Triton 3.6.x, 一次改 1286 个文件, 新增 30.7 万行并补 200 多个算子单测：[Ascend] Add Ascend backend support for Triton 3.6.x](https://github.com/flagos-ai/FlagTree/pull/1637)
- Torch-FL 八天八笔把 Qwen3-0.6B 热启动 CPU 提交从 211 毫秒压到 28 毫秒, 为厂商 PyTorch 的 1.17 倍：[perf: add generated native FlagGems hosts for eager inference](https://github.com/flagos-ai/Torch-FL/pull/824)
