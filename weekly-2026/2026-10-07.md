- EDG C++ 前端[现已开源](https://edgcpp.org/announcement/)。

- 北美 2026 年 LLVM Developers Meeting 的[报名截止日期为 10 月 16 日](https://discourse.llvm.org/t/2026-llvm-developers-meeting-hotel-t-shirt-size-guarantee-deadlines/91946)。

- Bruno Cardoso Lopes 分享了 [9 月 ClangIR 进展报告](https://discourse.llvm.org/t/clangir-progress-report-september-2026/91947)。47 个 SPEC CPU 2026 benchmark 中有 40 个可以编译并通过，2 个链接失败，5 个出现运行时失败（miscompile）。

- 【我们用英文翻译的怎么看】Nikita Popov 提议修改 LLVM 的 AI 工具政策，[禁止 AI 生成的交流内容](https://discourse.llvm.org/t/rfc-forbid-ai-generated-communication/92414)，目的在于阻止人们提交由 AI 工具撰写的 PR 描述与 RFC。

- Tom Stellard 就[我们在 GitHub UI 中合并 pull request 失败这一项目级问题](https://discourse.llvm.org/t/psa-project-wide-issue-with-merging-pull-requests-in-the-github-ui/91974)发布了一则 PSA。这是一个非常令人沮丧的状况。希望 GitHub 能尽快修复。

- Mitch Briles 发起了一场 RFC 讨论，关于[在后端中尊重 freeze 语义](https://discourse.llvm.org/t/rfc-respecting-freeze-semantics-in-backends/92408)。"AArch64、AMDGPU、RISC-V 和 X86 上的 SelectionDAG、FastISel 以及 GlobalISel 选择器都无条件地把 freeze/ISD::FREEZE/G_FREEZE 降低为 COPY。如果 freeze 的输入是 undef 或 poison，剩下的就是 IMPLICIT_DEF 的一个 COPY，而它表示一个 undef 值。ProcessImplicitDefs 与寄存器合并器随后把这个 COPY 视为未定义，于是不同的使用点就可能读到不同的寄存器。其后果就是由来已久的一系列 miscompile。"

- Yaxun (Sam) Liu 发布了一则 RFC，关于[为 llvm-cov 增加一个可选启用的选项，以便在覆盖率报告中排除被标注的源码行与区间](https://discourse.llvm.org/t/rfc-source-coverage-exclusion-markers-in-llvm-cov/91977)。

- Kunal Chadha 希望[新增一个属性，用于标示函数对某个指针参数所写入的字节区间](https://discourse.llvm.org/t/rfc-add-a-new-attribute-that-conveys-the-byte-range-written-to-by-a-function-for-a-pointer-argument/91948)。
