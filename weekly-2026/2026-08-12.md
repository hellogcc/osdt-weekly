### GCC

- **GCC 16.2.0 已发布!**
  - [https://inbox.sourceware.org/gcc/r8p34qp8-r1qq-9nn3-r499-1q833r6801n4@fhfr.qr/](https://inbox.sourceware.org/gcc/r8p34qp8-r1qq-9nn3-r499-1q833r6801n4@fhfr.qr/)

- [RISC-V: Allow RVV register overlap for vwmulsu.vv](https://gcc.gnu.org/pipermail/gcc-patches/2026-August/726008.html)
  允许 vwmulsu.vv 指令的 RVV 寄存器重叠, 放宽向量扩展乘法的寄存器分配约束, 消除不必要的移动指令。

- [RISC-V: Don't emit a separate multilib for the default march/mabi](https://gcc.gnu.org/pipermail/gcc-patches/2026-August/726020.html)
  默认 march/mabi 组合不再生成单独的 multilib 变体,简化多架构构建配置,减少重复的目标文件。

- [PATCH v4 4/5] RISC-V: Add macro-fusion pair recognition](https://gcc.gnu.org/pipermail/gcc-patches/2026-August/726043.html)
  为 RISC-V 增加宏融合(macro-fusion)指令对识别,将相邻指令(如 compare+branch)配对调度,提升流水线效率。

- [aarch64: Implement vector DImode high-part multiply using SVE for Advanced SIMD modes](https://gcc.gnu.org/pipermail/gcc-patches/2026-August/726022.html)
  Advanced SIMD 没有 64x64 高半乘法指令,本补丁在向量化需要 DImode 高半乘法时改用 SVE 实现,补齐 SIMD 代码生成能力。

- [rs6000: Add ABI and libgcc support for C23 _BitInt [PR117584]](https://gcc.gnu.org/pipermail/gcc-patches/2026-August/726030.html)
  为 PowerPC 增加 C23 `_BitInt` 类型的 ABI 与 libgcc 运行时支持,使任意精度整数类型可在该后端使用。

### BINUTILS

- [PATCH v13] aarch64: Implement Structured Exception Handling (SEH) on AArch64](https://sourceware.org/pipermail/binutils/2026-August/150707.html)
  在 AArch64 后端实现 Windows SEH 结构化异常处理(基于微软文档规范,复用共享辅助函数),gas 可生成 .pdata/.xdata(第 13 版,移除冗余逻辑)。
  （诶，这个以前没有么？）

- [bfd,binutils: add support for gfx1103](https://sourceware.org/pipermail/binutils/2026-August/150648.html)
  为 AMD gfx1103(RDNA3)目标增加 BFD/binutils 支持,与 GDB 侧支持保持一致。

- [PATCH v2] PowerPC: Initial SFrame support for 64-bit PowerPC ELF ABI](https://sourceware.org/pipermail/binutils/2026-August/150760.html)
  为 64 位 PowerPC ELF ABI 添加 SFrame(栈帧回溯信息)生成支持,扩展该格式到更多架构。

- AI时代是找漏洞的狂欢： [RFC: Fix for CVE-2026-19548](https://sourceware.org/pipermail/binutils/2026-August/150765.html)
  提出修复方案:ld/ldmain.c 中 add_archive_element() 存在 use-after-free 漏洞(CVE-2026-19548)。

### GLIBC


- [PATCH 1-5/5] riscv: Optimize C23 fmaximum/fminimum and use Zfa instructions](https://sourceware.org/pipermail/libc-alpha/2026-August/179595.html)
  RISC-V 浮点优化系列(5 个补丁):用 fmax/fmin 指令实现 C23 maximumNumber/minimumNumber;用 Zfa 扩展的 fmaxm/fminm 指令实现 NaN 传播语义的 maximum/minimum;并启用 Zfa 门控的 TOINT_INTRINSICS 与 ceil/floor/rint/round/trunc 等取整函数。

- [riscv: avoid vle8ff in vector strcmp loop](https://sourceware.org/pipermail/libc-alpha/2026-August/179651.html)
  RISC-V 向量 strcmp 循环中避免使用 vle8ff(容错加载),改用更安全的方式处理页边界,修复潜在问题。

- [PATCH 00/20] alpha: tune the memory and string routines, and add IFUNC dispatch](https://sourceware.org/pipermail/libc-alpha/2026-August/179703.html)
  Alpha 架构 20 补丁大系列:重调 memset/memcpy(基于 EV6/EV7 的 wh64 预取优化)等内存与字符串例程,并引入 IFUNC 动态分派。
  （Alpha架构竟然还活着）

- [PATCH] misc: Fix out-of-bounds array write in tdelete (bug 34506)](https://sourceware.org/pipermail/libc-alpha/2026-August/179685.html)
  修复 tdelete 中数组越界写: 直接分配最大数组大小,替代运行期扩容,消除 alloca 使用。
  （这是安全漏洞么？）

- [PATCH] LoongArch: Support pointer guard on LoongArch32](https://sourceware.org/pipermail/libc-alpha/2026-August/179652.html)
  LoongArch32 无 rotri 指令,用移位/或运算合成旋转实现指针保护,补齐 LA32 的强化特性。

### LLVM/Clang/LLDB/LLD

本节内容来自 [LLVM Weekly 第 658 期](http://llvmweekly.org/issue/658)，
[Alex Bradbury](https://www.linkedin.com/in/alex-bradbury/) 大哥持续稳定输出。

- 在美国，国内有伙伴去么？ 2026 年 LLVM 开发者大会(LLVM Developers' Meeting)的日程安排[已经公布](https://discourse.llvm.org/t/announcing-the-2026-llvm-developers-meeting-program/91470)。

- 又有一批 EuroLLVM 演讲视频[已上传至 YouTube](https://www.youtube.com/playlist?list=PL_R5A0lGi1ABJTIK5_5MkvHDb12mUmpSz)。

- 因特尔也是好起来了： Michal Paszkowski 及其同事提议[将 PISA 后端上游合并到 LLVM](https://discourse.llvm.org/t/rfc-upstreaming-the-pisa-backend-to-llvm/91474)。PISA(Portable Instruction Set Architecture,可移植指令集架构)是一种为新一代 Intel GPU 设计的虚拟 ISA。该后端完全使用 GlobalISel。

- 这个会不会重新做一个轮子： Raphael Isemann 发起了一个 RFC 提案线程,讨论[让 LLDB 摆脱使用 Clang AST 和类型系统的 `TypeSystemClang`](https://discourse.llvm.org/t/rfc-a-faster-more-reliable-type-system-for-c-languages/91459),以构建更快、更可靠的 C 语言类型系统。

- MLIR的新闻太多了，要整理也不容易：沉寂一段时间之后,Javed Absar 的 MLIR 新闻通讯[回归了](https://discourse.llvm.org/t/mlir-news-76th-edition-8th-august-2026/91513/1)。如果你想了解 MLIR 近期的 RFC 提案和变更,这里是最好的去处!

- 裸机也能做AS么？ Schrodinger Zhu 发起了一个 RFC 讨论,主题是[面向裸机(bare metal)环境的 address sanitizer](https://discourse.llvm.org/t/rfc-address-sanitizers-for-bare-metal-environments/91476)。

- 干得漂亮： 为 SpacemiT-X100 RISC-V 内核添加了向量调度信息。[00312bb](https://github.com/llvm/llvm-project/commit/00312bb11db4)。

- 改进了 LLVM 的 CMake 构建系统对增量文档构建的处理方式,不再遗留过期的文件。[263280e](https://github.com/llvm/llvm-project/commit/263280e39e6d)。

- 还有伙伴在用么？ 移除了 loop-extract pass,因为上游已没有任何地方使用它。[8277177](https://github.com/llvm/llvm-project/commit/827717745693)。

- 新增了 `llvm-gsymutil --statistics` 选项。[668134e8](https://github.com/llvm/llvm-project/commit/668134e8acf1)。

- 荣誉！ 为 XiangShan KunMingHu RISC-V 微架构添加了调度器定义。[fa01521](https://github.com/llvm/llvm-project/commit/fa01521e37e1)。

- Arm 内建函数已迁移到 tablegen。[de8c11a](https://github.com/llvm/llvm-project/commit/de8c11a66981)。
