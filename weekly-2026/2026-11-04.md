### LLVM/Clang/LLDB/LLD

本节内容来自 [LLVM Weekly 第 670 期](http://llvmweekly.org/issue/670)，
[Alex Bradbury](https://www.linkedin.com/in/alex-bradbury/) 大哥持续稳定输出。

- Timm Baeder 在 Red Hat 博客上发表了 [Clang 字节码解释器进展更新](https://developers.redhat.com/articles/2026/10/19/clang-bytecode-interpreter-update-2026)。

- Anton Korobeynikov 指出,[Graphite 评审工具将尽快对 LLVM 项目停用](https://discourse.llvm.org/t/graphite-will-be-disabled-asap/92689), 原因是该工具不再为开源组织提供折扣或免费方案。

- 上周 Dev Meeting 上各个圆桌会议/工作坊的纪要已经发布:[调试信息(debug info)](https://discourse.llvm.org/t/llvm-2026-dev-conf-debug-info-round-table/92500/7)、[LLVM hearts ML](https://discourse.llvm.org/t/llvm-dev26-llvm-ml-workshop/91148/2),以及 [RISC-V 圆桌会议](https://discourse.llvm.org/t/llvm-dev-meeting-2026-risc-v-roundtable-notes/92659/3)。

- Michael Kruse 介绍了[通过"去模板化(de-templatising)"提升 Flang 编译速度](https://discourse.llvm.org/t/rfc-the-cost-of-templates-when-building-flang/91197/12)这一工作的最新进展,并指出一个关键的 PR 即将合入。"Flang 的行为不应有任何变化,但构建速度最多可提升 46%(gcc,未使用预编译头)"。

- Ralf Jung 发起了关于[新增 freezing memcpy](https://discourse.llvm.org/t/rfc-add-a-freezing-memcpy/92637) 的 RFC 讨论,这是向程序员暴露 Rust 中 `freeze` 语义的整体方案的一部分。

- Joshua Haberman 发布了关于 [`tail_chaincc`:一种极致效率的尾调用约定](https://discourse.llvm.org/t/rfc-tail-chaincc-a-maximum-efficiency-tail-call-convention/92661)的 RFC。它结合了 `tailcc` 的被调用者清理(callee-cleanup)机制与 `preserve_none` 的寄存器优化,设计用于配合 `[[clang::musttail]]` 使用。

- paperchalice 撰写了关于 [TableGen 支持 RegisterBankInfo](https://discourse.llvm.org/t/rfc-tablegen-support-for-registerbankinfo-v2/92662) 的 v2 RFC,提供了一种通过匹配 `TypedOperand` 来定义寄存器分库(register bank)映射规则的方式。

- Federico Bruzzone 发布了一份 MLIR RFC,讨论[统一 Vector dialect 中的掩码(masking)处理](https://discourse.llvm.org/t/rfc-unify-masking-in-the-vector-dialect/92675)。

- Konstantin Zhuravlyov 发起了关于[由厂商负责的 LLVM PR 合入前测试(vendor-owned pre-merge testing)](https://discourse.llvm.org/t/rfc-vendor-owned-pre-merge-testing-for-llvm-prs/92624)的讨论。

- VPlan 现在会计算分支代价(branch cost)。[999b73d](https://github.com/llvm/llvm-project/commit/999b73deef74)。

- LLVM 的 libc 中,双精度 sinh、cosh、tanh 现在在所有舍入模式下都能正确舍入。[1866d4c](https://github.com/llvm/llvm-project/commit/1866d4cc5634)、[075a6cb](https://github.com/llvm/llvm-project/commit/075a6cb14025)、[ff9ad99](https://github.com/llvm/llvm-project/commit/ff9ad993c2b9)。

- LLVM libc 的正则表达式(regex)实现正在逐步完善。[ad46922](https://github.com/llvm/llvm-project/commit/ad46922aac46)、[adb8031](https://github.com/llvm/llvm-project/commit/adb80317aa28)。

### RT-Thread 社区

- 先楫半导体 13 分钟内把 12 个 RT-Thread BSP 仓库推到 v1.13.0, 并新开 HPM5100EVK, 示例覆盖 CAN、USB 双角色与 FlashDB: [rtt-bsp-hpm5100evk](https://github.com/hpmicro/rtt-bsp-hpm5100evk)- timerfd 的 settime/gettime 不校验 fd 类型, 非特权进程可用 signalfd 伪造对象并在 qemu-vexpress-a9 上劫持内核 PC: [[Bug] timerfd: timerfd_settime()/timerfd_gettime() accept any fd -> type confusion -> kernel PC control from an unprivileged user process](https://github.com/RT-Thread/rt-thread/issues/11984)
- POSIX timer 的 id 未做上限检查, RT-Smart 上可用下标 13733 改写 _console_device 的 ops 跳 EL1: [[Bug] libc: unchecked POSIX timer id in RT-Smart enables EL1 callback execution](https://github.com/RT-Thread/rt-thread/issues/11980)
- USB device 两笔旧账同小时合入, 字符串描述符索引越界与 MS OS 兼容 ID 长度不钳制均修掉, 主机可控长度不再越界读: [usbdevice: validate string descriptor index](https://github.com/RT-Thread/rt-thread/pull/11545)
- getaddrinfo 加固合入, 用 lwp_get_from_user 一次快照 res 与 hints, 57 行新增 17 行删除, 补上嵌套指针的 TOCTOU 缺口: [[components][lwp] harden sys_getaddrinfo user pointer handling](https://github.com/RT-Thread/rt-thread/pull/11977)
