### LLVM/Clang/LLDB/LLD

本节内容来自 [LLVM Weekly 第 657 期](http://llvmweekly.org/issue/657)，
[Alex Bradbury](https://www.linkedin.com/in/alex-bradbury/) 大哥持续稳定输出。

* 这些术语确实不好翻译成中文： Luke Lau proposes [adding an llvm.mask.beforefirst intrinsic](https://discourse.llvm.org/t/rfc-incrementally-enabling-the-newpm-for-codegen/91410O) that the loop vectoriser would use for generating exit masks use during early exit vectorisation. The second half of the RFC muses on when it's worthwhile introducing a new intrinsic.

* 这个patch貌似巨大，宋教授站出来进行了一个详细的讨论，认为这个有很多地方都需要重新审视。
  Shilei Tian started an RFC discussion on [link-time finalisation for separately compiled AMDGPU device code](https://discourse.llvm.org/t/rfc-link-time-finalization-for-separately-compiled-amdgpu-device-code/91457).
  “我们提议在 LLVM 中构建一种架构，以支持 GPU 设备代码的可扩展独立编译，并以 AMDGPU 作为首个实现目标。独立生成的设备目标文件（device objects）可包含针对各个函数的资源信息；然而，内核（kernel）的最终资源需求取决于从其他设备目标文件中选取的定义以及这些设备函数所需的资源。因此，只有在完成最终的目标文件链接解析后，才能确定完整的资源需求。本 RFC 首先阐述了这一通用的最终确定（finalization）需求，随后提出了一种 AMDGPU 实现方案，该方案在常规 ELF 链接过程与 AMDGPU 专属的资源分析逻辑之间定义了一个精简的接口。”

* 巨大改进： The RISC-V backend learned to deduplicate frame base address materialisations for large stack frames, leading to an 18% performance improvements on SPEC CPU 2026 'cactus' benchmark on the SpacemiT K3.
  [4120b5f](https://github.com/llvm/llvm-project/commit/4120b5f5a377).

* LLVM确实需要： Documentation was added for self-hosted runners on GitHub.
  [0fa9cfa](https://github.com/llvm/llvm-project/commit/0fa9cfa56727).

* 好看么： The Furo theme is now used for LLVM documentation. You can [see it in action here](https://llvm.org/docs/).
  [c44443f](https://github.com/llvm/llvm-project/commit/c44443f22b6f).

* 新的扩展又双叒叕出现了： MC-layer and codegen support was added for the experimental RISC-V Zilx (indexed integer load instructions) extension.
  [23a2224](https://github.com/llvm/llvm-project/commit/23a22244b099),
  [8a1ff7f](https://github.com/llvm/llvm-project/commit/8a1ff7feefc5).
